# Phase 5 — downloadable Quran for owner review

Branch `phase_5/quran-download-delivery`, based on merged phase 4 (`7f9034e`). This phase closes the normal download-and-read gap before proceeding to prayer/Qibla/adhan implementation. The owner's [manual Arabic reading-review deferral](../phase-4/REVIEW-DECISION.md) remains in force; it is not recorded as a completed religious review.

## Try it

Open the Quran tab, select Warsh or Hafs from **اختيار المصحف**, then use **تنزيل المصحف → تنزيل هذا المصحف**. After installation, open any surah; selecting an edition by itself never downloads it. Both editions can remain installed. Use Settings to switch light/dark mode, and the storage screen to remove an edition when needed.

## Delivery design

The normal bundled catalog now contains Warsh and Hafs. Selecting an edition still does not download anything. The explicit download action retrieves original files over HTTPS; the existing coordinator verifies their pinned sizes and SHA-256 values, then prepares and verifies the offline reading files on the phone. Only a completely verified import becomes readable. No login, application backend, local test server or new corpus hosting is required.

- **Warsh:** the original King Fahd v2.1/update 6 ZIP from the existing quran.ws byte-preserving mirror, pinned to the same publisher-corroborated archive as phase 1. The importer extracts only the explicitly named/hash-checked JSON, font, original Word document and README. It preserves all 6,214 verse strings and source IDs. The matching original King Fahd font remains mandatory.
- **Chapter openings:** the original Word document contains 114 surah headings and 113 following basmala paragraphs. Those paragraphs are preserved exactly, including source spacing/marks, and displayed separately from numbered verses. At-Tawbah receives no added opening. Nothing is transcribed or generated by AI.
- **Hafs:** the original Tanzil Uthmani 1.1 text, downloaded directly from Tanzil, with all 6,236 verse strings and its notice preserved. Its existing Noto Sans Arabic application font downloads from an immutable, already-published repository commit; it is not described as a Tanzil-provided font. The OFL notice accompanies the source information. Tanzil's source already includes its chapter-opening text; the importer does not split or duplicate it.
- **Translations/audio:** no translation or recording is newly offered by this phase. Their existing UI/runtime remains; this change delivers the two Arabic mushafs requested for reading review.

`tools/phase5/catalog.py` verifies locked originals and deterministically generates metadata, notices and hashes in `src/features/quran/catalog.data.json`. It does not publish text/font/archive files. Each local chapter has its own expected size/hash computed independently by the maintainer tool; the on-phone TypeScript parser must reproduce those exact bytes. The Android ZIP/document adapter is bounded, writes only declared private targets, rejects unsafe XML and checks original member hashes. Originals/notices remain on the phone alongside generated files.

The reader is keyed by its validated edition/surah/verse/version locator. Switching from a long chapter to a short one no longer renders the old chapter with the new verse bounds before the load effect runs; the offline At-Tawbah → An-Nas journey exposed and verifies this crash fix.

The coordinator tracks generated files as part of the installation so storage totals, deletion, interrupted-import recovery and retries own them. Failed import does not activate the new version or deactivate a previous ready version. Explicit downloading works again after cancellation/removal. A changed upstream file fails its pinned checksum; the app does not silently accept a new edition.

## Source and permission boundary

This delivery **does not create or publish a repackaged King Fahd corpus or a new mirror**. It downloads the existing unchanged archive and converts its container locally. The previously unresolved basis for hosting our own derived text pack therefore remains a separate future-hosting question, rather than a prerequisite for this original-source delivery path. Do not describe that distinction as a new blanket license grant or publisher endorsement.

The source origin, mirror and original font notices are disclosed in-app. The [publisher developer page](https://qurancomplex.gov.sa/en/techquran/dev/) identifies the developer package; direct publisher access remains unreliable here. Provenance/checksum corroboration is recorded in [the source decision](../../feasibility/android/WARSH.md). [Tanzil's text conditions](https://tanzil.net/docs/Text_License) require verbatim text and retained attribution/notice. The owner selected these sources; no further source-choice or full manual reading approval is requested.

## Reproduce

```sh
python3 tools/phase5/catalog.py --check
python3 tools/phase5/verify-source.py
npx tsc --noEmit
node --test tools/foundation/*.test.cjs tools/phase3/*.test.cjs tools/phase4/*.test.cjs tools/phase5/*.test.cjs
yarn feasibility:test
```

Source checks require the locked originals under `.roqia-feasibility/sources`; generated catalogs include metadata only. The Java archive test can be compiled with `SourceArchive.java` and run using JDK 21; its inputs are synthetic and it publishes no Quran data.

For a review APK that can cold-start offline without Metro:

```sh
JAVA_HOME=/path/to/jdk21 ANDROID_HOME=/path/to/sdk ./android/gradlew -p android :app:assembleReview -PreactNativeArchitectures=arm64-v8a
adb -s emulator-5554 install -r android/app/build/outputs/apk/review/app-review.apk
```

The review variant embeds production JavaScript, uses the development signing key/native library variants, and permits local inspection. It disables developer support and does not register the debug fixture entry point. It is **not a signed Play release**. Do not uninstall or clear data when installing it over the existing development build.

`tools/phase5/android-offline.py --output /private/tmp/roqia-phase5` wraps the reader journeys with airplane mode and Wi-Fi/mobile-data disabled, restoring the prior network settings even on failure.

`tools/phase5/android-journeys.py` exercises only the normal `MainActivity` on `emulator-5554`. The `downloads` section expects neither production pack installed and Warsh selected; the `readers` section expects both installed. Back up data before running journeys. Keep the resulting Quran downloads for owner review and preserve existing counters/bookmarks/settings.

## Android evidence — 18 October 2026

Validated only on `emulator-5554`, Android 16/API 36, arm64-v8a. The attached physical device was not used. The final standalone review APK built successfully and was installed in place, with both Quran editions retained for owner reading review.

- TypeScript passes; **55 focused tests**, **21 feasibility cases** and **7 native archive checks** pass. All **228 chapter outputs** match independently generated locked-source hashes.
- Normal `MainActivity` completed actual HTTPS downloads, opened both readers, removed both test-created packs through Storage, and downloaded them again. This uses no debug fixture catalog or local server.
- Airplane mode, Wi-Fi off and mobile data off: cold-start reading passed in light and dark modes, covering Al-Fatiha, At-Tawbah and An-Nas in both editions. The long-to-short chapter navigation crash found during this check is fixed and the same journey passes. Prior network settings were restored.
- Independent extraction from the emulator verified **all 235 installed files** against the catalog (119 Warsh, 116 Hafs), with two active ready packs and three ready source jobs. **All 207 existing counter rows and all 9 pre-existing records** were preserved; preferences changed by testing were restored.
