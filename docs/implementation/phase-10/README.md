# Phase 10 — durable download recovery and Wi-Fi policy

Branch: `phase_10/download-recovery`. Tickets: [RQ-020](../../../design/roqia-v2/implementation/tickets/RQ-020.md), [RQ-021](../../../design/roqia-v2/implementation/tickets/RQ-021.md). Shared coordinator changes with Android native validation first; iOS acceptance is deferred. Whole-app screenshot parity, including Prayer/Qibla, remains unaccepted and outside this phase.

## What changed

The pinned downloader remains **4.6.3**, with MMKV **1.3.16** and file-access **4.0.4**. A checked-in [Android patch](../../../tools/phase10/downloader.patch) adds the guarantees missing from its upstream transport. Install and Android build both run a version/hash-checked, idempotent patch step; unexpected dependency drift fails the build. A clean-copy round-trip test verifies patch application, repeat application and drift rejection.

Wi-Fi means the Android **Wi-Fi transport**, including metered Wi-Fi. Unmetered mobile data or Ethernet does not satisfy it. Native UIDT jobs and the older foreground-service gate use the same constraint and bind connections to the permitted network. An explicit any-network choice remains a separate persisted consent. A waiting file offers a confirmation that grants this consent only to that file; its native task restarts while other jobs retain their Wi-Fi policy. The shared coordinator also checks the network type, refetches it on foreground return, retains network-paused intent, and never turns a user pause into automatic network recovery.

Partial files retain a synced entity sidecar containing original URL, strong ETag (or Last-Modified) and response length. The actual file length determines the resume offset, independently of throttled progress snapshots. Before append, native code requires a valid 206 range start/end/total, body length and unchanged validator. It sends `If-Range` with identity encoding. A 200 replaces bytes; an invalid 206/entity change restarts once from zero; 416 either recognizes a potentially complete file for final verification or restarts. Missing validators cause a full replacement. Manifest size bounds unknown-length transfers. Every success still requires exact size, SHA-256, type signature and source/derived structure checks; HTTP success is never installation proof.

Android file installation syncs the source, uses same-filesystem `Os.rename`, syncs affected directory ancestors, then syncs all originals/derived outputs before publishing ready. SQLite uses WAL with `synchronous=FULL`; the install journal precedes rename and the activation transaction follows synced files. Sync failure leaves an inactive installation, with recovery/retry available. A complete private file can be recovered when native completion happens before JavaScript receives its event. Older installed versions and unrelated completed content remain intact.

User-facing states distinguish waiting for a permitted network, explicit pause, failed verification and low space. Resumed transfers explain safe restarts when the server cannot confirm the partial entity. Generated numbers remain Western 0–9.

## Reproduce

Back up the populated emulator first. Use **emulator-5554 only**; never uninstall or clear app data.

```sh
python3 tools/phase10/patch-downloader.py
python3 -m unittest discover -s tools/phase10 -p 'test_*.py'
node --test tools/foundation/*.test.cjs tools/phase3/*.test.cjs tools/phase4/*.test.cjs tools/phase5/*.test.cjs tools/phase6/*.test.cjs tools/phase8/*.test.cjs tools/phase9/*.test.cjs tools/phase10/*.test.cjs
./node_modules/.bin/tsc --noEmit
cd android
ANDROID_HOME="$HOME/Library/Android/sdk" JAVA_HOME="$HOME/.sdkman/candidates/java/current" ./gradlew :app:assembleReview :app:assembleDebug -PreactNativeArchitectures=arm64-v8a
```

Controlled transport tests use the debug-only feasibility activity, production ports/coordinator, isolated `phase10-*` records/files, `tools/phase10/fixture-server.cjs` on port 8084 and Metro on port 8081. Reverse these ports on the named emulator. `tools/phase10/android-matrix.py` records each scenario, performs app-only SIGKILL at explicit checkpoints, and restores network availability. `native-wifi` intentionally tells the coordinator that Wi-Fi is available while actual Wi-Fi is off: the native job must wait without requesting fixture bytes. `any-network` exercises explicit consent with Wi-Fi off. Fixtures are synthetic JSON; no synthetic Quran/audio pack enters the production catalog.

Real-provider tests are separate: install `android/app/build/outputs/apk/review/app-review.apk` in place, then run `tools/phase10/android-real.py --output <directory> --section audio`, `translation`, `offline` and `cleanup-audio`. Use `resume-audio` to continue a retained user pause, or `retry-audio` to retry a failed provider transfer over restored Wi-Fi. Storage locators reacquire labels as byte totals load, and scroll gestures overlap so controls are not skipped. The review variant bundles production JavaScript, has no feasibility activity, and needs neither Metro nor the fixture server. The hierarchy helper must already be on the emulator; each dump removes the previous XML first.

## Validation and limits

The final review/debug builds and TypeScript pass, with **79 shared automated tests**, one dependency-patch round-trip/drift test and **22 controlled Android scenarios**. Eighteen scenarios produce verified files, three reject unavailable/corrupt/no-space inputs, and one proves cancellation removes bytes. The matrix includes valid 206, wrong-offset 206, changed entity, 200 replacement, incomplete/complete 416, Last-Modified-only/no-validator responses, unknown length, user pause, active process loss, before/after rename and before activation commit, background transfer, Wi-Fi loss/return, native-only Wi-Fi enforcement and explicit any-network consent. See [validation/build identity](evidence/validation.json), [matrix](evidence/android-matrix.json), [HTTP requests](evidence/http-requests.json), [native pending Wi-Fi job](evidence/native-wifi-job.txt) and [test log](evidence/tests.log).

The normal review build downloaded the real MP3Quran Warsh surah 112 file: **243008 bytes**, matching its pinned SHA-256. Its initial cellular-only provider attempt failed after three native I/O errors (`-1`), retaining the job and all older content. An explicit Wi-Fi retry succeeded on its first attempt. The cellular network was not validated in the emulator's connectivity snapshot; successful real-provider cellular delivery is **not claimed**. Native policy/consent enforcement is separately proved by the controlled matrix. User pause survived force-stop/reopen and network return before the explicit continuation/consent actions. See [real-provider result](evidence/real-provider.json).

English Pickthall was selectively removed through Storage and downloaded directly from Tanzil again; the source import and all expected outputs must pass before activation. French stayed selected. Offline cold-start Hafs/French and King Fahd Warsh reading passed. The final [backup comparison](evidence/android-integrity.json) confirms **207 counters, 1 bookmark, 3 reminders, both reader preferences, app settings and prayer preferences/sounds** are preserved. **All 469 original content files are byte-for-byte identical** and every expected installed catalog hash matches. Only the reinstalled English pack's activation timestamp changes; reading-position identities remain, with positions allowed to reflect test navigation. The new test audio was removed through Storage. Isolated fixture records/files were cleaned up, network was restored, the original dark theme and French selection remain, and the installed review app was reopened. No uninstall or data clear occurred. [Captures](SCREENSHOTS.md) are functional evidence, not visual acceptance. Mechanical hashes establish byte integrity, not editorial certification. The selected Arabic editions/fonts, translations, source URLs, pack versions and catalog identities are unchanged.

The emulator is Android 16 / API 36 arm64. App-only process loss differs from **force-stop**: Android suspends force-stopped work until the user reopens the app. Neither this phase nor the downloader promises transfers while force-stopped. Background/reattachment observations apply to this emulator; older Android foreground-service execution, physical devices/OEM scheduling, true sudden power loss and real filesystem exhaustion remain RQ-048 acceptance work. Low-space preflight and injected sync/transaction failures are tested without filling the user's emulator disk. iOS native/build/device acceptance remains deferred; its transport retains safe restart behavior rather than claiming the Android resume/durability extension.
