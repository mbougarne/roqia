# RQ-001 — Capture current release and compatibility baseline

Status: **planned** · Milestone: **M0**

Dependencies to start: None.

Screens: Foundation / cross-cutting.

## Scope

Record current dependency APIs, build/install path, app ID, released version and device baseline. Inventory content IDs, bundled audio, reminder behavior and existing screen routes. Record failures before changing dependencies.

Likely implementation touchpoints: package.json; yarn.lock; android/; src/App.tsx; __tests__/. These paths are targets, not changes already made.

## Acceptance criteria

- [ ] A reproducible current install and in-place upgrade route are recorded.
- [ ] Current source versus Play release differences are explicit.
- [ ] Existing counter/audio/notification journeys have baseline evidence.

## Validation

Run existing checks and Android build/install where configured; record failures without silently repairing unrelated tooling.

## Handoff and completion

Record the implementation commit/build, changed paths, actual checks, device/OS where applicable and unresolved limitations. Link related screen captures and source-pack versions. Update this file and backlog.json together. Do not mark done from a mockup or a dependency README alone.

Follow the [architecture](../../architecture/ARCHITECTURE.md), [design system](../../specs/DESIGN-SYSTEM.md) and [acceptance plan](../../qa/ACCEPTANCE.md). Preserve existing user data and avoid unrelated refactors.
