## Phase 10 — Android download recovery and network policy

Android functional implementation complete on `phase_10/download-recovery`; broader native acceptance remains open, so status stays `in_progress`. The [phase 10 report](../../../../docs/implementation/phase-10/README.md) supersedes the earlier strict-Wi-Fi/range/fsync and restart-from-zero limitations **on Android**.

Pinned downloader 4.6.3 has a version/hash-checked Android extension for Wi-Fi transport constraints, entity sidecars, exact pre-append 206 validation, safe 200 replacement/416 recovery, bounded unknown-length writes and completion fsync. The shared coordinator preserves user/network-paused partials, recovers completed files across lost native callbacks, ignores stale generations, and publishes only after native file/directory sync and the journaled SQLite activation commit. WAL commits explicitly use synchronous FULL. UI exposes pause versus network wait, safe server restarts and low-space recovery.

Controlled HTTP/process-loss checks use the production adapter/coordinator in isolated debug records; real-provider checks use the normal bundled-JS review build separately. The report records exact test outcomes, file hashes, preservation checks and captures. No source/catalog identity or Arabic/font/translation content changes.

**Remaining acceptance:** Physical/OEM and older supported Android coverage, actual power-loss/disk-exhaustion testing and the broader RQ-048 matrix; iOS native/build/device verification is deferred. API 36 evidence is not proof of those platforms. Force-stop suspends work until reopening. No screenshot-parity acceptance is claimed.
