## Scope

This is the final acceptance audit, not the place to defer all design implementation. RQ-051–RQ-062 explicitly implement the 48 reference screens first. Track each theme separately in [VISUAL-COVERAGE.md](../VISUAL-COVERAGE.md); a functionality-only screenshot does not satisfy visual parity.

Capture all 48 screens in both themes from the running app and compare semantic layout to kit. Resolve differences consistently via tokens; validate TalkBack and large text.

Likely implementation touchpoints: UI acceptance captures; shared components. These paths are targets, not changes already made.

## Acceptance criteria

- [ ] 96 implementation captures indexed.
- [ ] Compact headings/Western digits and all target sizes pass.
- [ ] No clipped Arabic/translation text or inaccessible action.

## Validation

Device screenshots at multiple widths/font scales; TalkBack and contrast report.

## Handoff and completion

Record the implementation commit/build, changed paths, actual checks, device/OS where applicable and unresolved limitations. Link related screen captures and source-pack versions. Update this file and backlog.json together. Do not mark done from a mockup or a dependency README alone.

Follow the [architecture](../../architecture/ARCHITECTURE.md), [design system](../../specs/DESIGN-SYSTEM.md) and [acceptance plan](../../qa/ACCEPTANCE.md). Preserve existing user data and avoid unrelated refactors.
