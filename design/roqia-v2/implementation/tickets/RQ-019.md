# RQ-019 — Publish a versioned static content catalog

Status: **planned** · Milestone: **M3**

Dependencies to start: [RQ-018](RQ-018.md).

Screens: 23, 24, 28, 32, 33.

## Scope

Create immutable ready pack metadata using the schema. Choose approved direct files or static host, record sizes/hashes/attribution and bundle a small seed catalog. Exclude drafts from installable UI.

Likely implementation touchpoints: src/content/catalog/ (future); static content release tooling. These paths are targets, not changes already made.

## Acceptance criteria

- [ ] Every ready entry resolves to validated artifacts.
- [ ] No secret or executable code in catalog.
- [ ] Offline last-good catalog works; provider failure preserves installed content.

## Validation

Catalog schema/semantic validation, actual download-host probes and bundled-seed offline test.

## Handoff and completion

Record the implementation commit/build, changed paths, actual checks, device/OS where applicable and unresolved limitations. Link related screen captures and source-pack versions. Update this file and backlog.json together. Do not mark done from a mockup or a dependency README alone.

Follow the [architecture](../../architecture/ARCHITECTURE.md), [design system](../../specs/DESIGN-SYSTEM.md) and [acceptance plan](../../qa/ACCEPTANCE.md). Preserve existing user data and avoid unrelated refactors.
